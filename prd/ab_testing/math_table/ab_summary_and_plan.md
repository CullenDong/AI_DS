# Fancy Stuff（Convex Bandit）数学表优化：A/B 实验总结与后续计划

## 名词说明

- **Fancy Stuff**：Convex Bandit Optimization（下文简称 CBO）模型的昵称。它是一个强化学习模型，学习 base game 的赔付分布（basis weights）和 trigger rate，并通过 Esscher transform（指数 tilting）构成的投影层，把学出来的分布强制收敛到给定的 RTP 目标上，用来根据真实玩家的下注数据调整、制作数学表，改善用户体验与游戏营收。
- **数学表**：一份具体的赔付分布 + trigger rate 配置，来源上分三类——CBO 训练产出（bgtr 系列）、纯 Esscher RTP 平移但不改变分布形状（95Kai / 93Kai）、原生未改表（zero / shi / ni / san / go / roku / ichi）。
- **MAB**（Multi-Armed Bandit）：平台侧负责"把哪张表分给哪群用户"的选表算法层，和负责"生成、优化表本身"的 CBO 是两套系统。本文只覆盖 CBO 产出表格的 A/B 上线过程，MAB 算法自身的版本升级只作为背景时间点提及。
- **分组**：2026 年 8 月 3 日之前按具体表名直接切换 Default / TestA / TestB；之后改为按 user_id 尾号分组——Default 对应尾号 0-3，TestA 对应 4、5，TestB 对应 6、7，新增的 AI 组对应 8、9。
- **核心指标**：bet_med（模拟人群终身下注总额 total_bet 的中位数）、sess_mean（人均 session 数）、one_and_done（只玩一次 session 就不再回来的用户占比）、retention（P(n_sessions>1)），以及后文会用到的 num_bet（下注笔数）。
- **模拟器的定位**：模拟器目前做不到精确的定量预测，绝对值不能直接当业务预测使用；它能做的是候选表之间的比较和方向性判断（谁比谁好、往哪个方向变），后文所有模拟数字都应该按这个定位来读。

## 总结（结论速览）

> 一句话：**决定数学表业务价值的不是 RTP 的高低，而是"多出/少掉的 RTP 花在哪个赔付环节"**——交给 CBO 重塑 BG 节奏（95bgtr/97bgtr）能同时拉动下注与留存；单纯平移 RTP（95Kai/93Kai）是中性；粗暴提 BG 中奖率（97BG）适得其反。且数学表的作用**几乎只落在中/大额、资深玩家**身上。

### 每期结论

- **一期（95Kai、97BG vs zero）**：95Kai（只平移 FG RTP、不改形状）与 zero **基本持平**——单纯调 RTP 不改行为；97BG（提 BG 中奖率、空转 70%→35%）**全面变差**（num_bet −27%、D1 −4.2pp，越资深越差），证伪"高频小奖改善体验"。两条相反偏差直接催生了模拟器矫正。
- **P1（93Kai）**：93Kai（Esscher 压得比 95Kai 更深）**不及 95Kai**（num_bet −3.7%、D1 −3.2pp），伤害集中在资深段，但明显好于 97BG——划出了"平移 RTP"的甜点（≈95）与下界。
- **二期（95bgtr、shi）**：95bgtr（首张 CBO 自由演化训练表）**首次全面跑赢 95Kai**（num_bet +21%、留存微升、GGR 仍为正）——CBO 训练路线跑通、项目正向拐点。shi 低量却黏人，暴露"下注量 ↔ 留存"目标背离。
- **三期（97bgtr、95bgtr）**：两张 BGTR 表同期**都显著跑赢 95Kai**（num_bet +25~29%、留存升）；97bgtr RTP>100、GGR 转负（对大玩家让利换活跃/留存）。**增益随玩家资历与额度放大**。

### 每张数学表：设计改动点 → 数据反馈

一张数学表 = 一份「base game（BG，普通旋转）赔付分布 + free game（FG，免费游戏）表现 + trigger rate（进 FG 的触发率）」配置，`总RTP = BG_RTP + FG贡献`（FG贡献 = trigger率×E[免费轮数]×FG均值）。改 RTP 就是动这三段之一。按**改动手法**分三家族：① **原生未改**（zero/shi…）；② **Esscher 平移**（95Kai/93Kai，把每个赔付倍率 x 的概率 ×`e^(θx)` 再归一、θ 解到命中目标 RTP；θ<0 会**指数级压低高倍率大奖、概率挪向小额与 0 赔付**，即"压 RTP 压的是大奖尾部"、分布形状不变）；③ **CBO 训练**（bgtr 系，RL 重学 BG 赔付分布 + trigger，再经 Esscher 投影层收敛到目标 RTP）。下表「设计改动点」的数值均取自设计方原始统计。

### 优秀数学表的实际效益（vs 现行 95Kai，同期、刨暗保底）

- **95bgtr（CBO 自由演化）**：三期 num_bet **+28.6%**、人均投注 **+27%**、留存微升，且 **GGR 仍为正（+15.0 万）**——不牺牲平台毛利就把量与留存一起抬起来；二期已复现同向（num_bet +21%、GGR +12.1 万）。
- **97bgtr+BGadj（RTP97·BG 重分配）**：三期 num_bet **+25.3%**、人均投注 **+28%**、留存 **D1 +1.8pp**；对**大额玩家**尤为明显（净亏中位 −385→−190、缩尾均值转正），代价是 GGR 转负 −13.6 万（对大鲸让利换其活跃/留存）。
- **共同效益与落点**：两张 CBO 表把**中/大额、资深玩家**的下注量与留存同时抬升（小额玩家占人数六成却对表不敏感、一次性居多）。CBO 训练闭环已验证有效，**95bgtr/97bgtr 可作后续 default 候选**；两者取舍就在"要不要为多约 1pp 的活跃/留存去付出转负 GGR"。

## 口径说明（数据组回填真实 A/B）

本文各「真实 A/B（数据组回填）」表格由数据组从 `slot-machine.public.fct_bet_orders`（`game_id='SS03'`、CNY、`status='COMPLETED'`、剔除测试单 `op_code NOT IN (B26,TST,TSB,TSO)`）统计，取数口径统一如下：

- **只做同期对比**：user_id 尾号分组 2026-08-03 才上线，之前按 `partition_ab` 分组——同一组名在切换点前后是两拨不同的人。因此每期只在**同一时段内**横比各组（同随机人群、同环境、同暗保底），唯一差异 = 数学表；跨期数字不能直接相减。
- **分组核对**：切换前按 `partition_ab[0]`、切换后按 `MOD(user_id,10)`（Default 0-3 / TestA 4,5 / TestB 6,7 / AI 8,9）。各期每组的主基础表已用真实数据逐一核对（排除 kakutei 暗保底表后取该组去重用户最多的表），与第二节时间线完全一致。
- **指标定义**：
  - **汇总额**：`总投注次数(万)` = 该(组/层)内 `bet_amount>0` 的总 spin 数（下注笔数总量，单位万次）；`总投注额(万)` = Σ `bet_amount`；`总payout(万)` = Σ `actual_payout`（含 FG 全部行）；`总GGR(万)` = 总投注额 − 总payout = 平台毛收入（正 = 平台赚、负 = 该组玩家整体赢，对应 RTP>100）。
  - **`RTP%`** = 总payout ÷ 总投注 ×100（含 FG）。
  - **三视图 `中/均/均99`**：每个"人均"指标同列给三个数——`中`=中位数（典型玩家）、`均`=原始均值（含鲸鱼、易被极端户拉飞）、`均99`=**0–99% 缩尾均值**（削掉最高 1% 后的均值，稳健口径）。三者差得越大，说明该格鲸鱼偏斜越重（应以中位/均99 为准，`均` 仅供看头部体量）。
  - **`num_bet`** = 下注笔数（`bet_amount>0`）；**`人均投注`** = 每人总投注额；**`人均净`** = 玩家净额（`payout − bet`，负 = 玩家净亏）——三者均给 `中/均/均99`。
  - **`单发金额 均/中`** = 单次投注额（逐笔 `bet_amount`，`bet>0`）的**均值 / 中位数**（行级 `PERCENTILE_CONT`），衡量玩家在该表上的**单笔投注力度**：中位=典型玩家单笔押注、均值=含鲸鱼的整体单笔强度；两者差得越大＝加注集中在头部大户。
  - **`D1/D3/D7`** = day-N 当日回访留存（按北京日、当天有投注即活跃、不去重、右截断置空）。
- **暗保底已整行刨除**：所有指标只统计**基础表服务的 spin**，`normal_kakuteiA/B/C`（暗保底/確定表）整行剔除。暗保底是与数学表并行的独立一层（约占 1–1.5% spin、会抬高 RTP 约 0.2–0.8pp），刨除后 RTP/GGR/净额/投注干净反映**基础表本身**；这也顺带消除了下文第七节担心的"换表与暗保底同日切换"混淆。（注：组间 delta 对暗保底本就近乎相抵，刨前刨后结论不变，仅绝对值更纯。）
- **AI 组**为多表混合（非单一表臂），仅列作参考、不作干净对照。窗口截至最后可用北京日。
- **玩家生命周期（日龄）分层**：每期在总体表之外，再按玩家**自首发子弹（全历史第一发 `bet_amount>0`）起算的自然日龄 d** 切三层——**new（0-3 天）/ beginner（4-7 天）/ old（≥8 天）**（实现为 `d<=3→new, d<=7→beginner, else old`）。日龄按 user-day 计（同一玩家不同天会随日龄增长跨层），故各层去重用户可重叠、层内"人均"= 该玩家落在该层的那些天的汇总。每层内仍与同期同层的 Default 对比。
- **玩家投注额分层**：另按玩家**期内总投注额**切三档——**小投注额（<200 元，约 63% 玩家）/ 中投注额（200–2000 元，约 29%）/ 大投注额（≥2000 元，约 8% 玩家却占约 86% 投注额）**。阈值取整、跨期通用（四期总投注额分布高度稳定：P50≈100–130、P90≈1300–1800、P99≈2 万）。此为按玩家（非 user-day）分档，每人整期归一档；每档内仍与同期同档的 Default 对比。

## 一、优化流程

数学表的迭代使用以下闭环流程：

1. 用真实交互数据构建供强化学习训练和数学表评估用的模拟器
2. 用模拟器辅助优化并选出候选数学表
3. 交给真实 A/B 测试检验
4. 用 A/B 的真实结果去修正模拟器里已知的偏差
5. 基于修正过的模拟器重新训练下一版数学表

目前已经走过两轮这样的循环。

## 三、一期：95Kai_FGadj 与 97BG_adj

一期两张表并行上线，边界设定不同：

- **95Kai_FGadj**：只用 Esscher 变换整体下调 FG RTP，不改变赔付分布形状，作为隔离 CBO 超额收益的对照锚点。
- **97BG_adj**（bg97_best）：锁死 Free Game 表现和 trigger rate，只重塑 Base Game 的赔付节奏，算法把空转率从 70% 压到 35%。

上线前的单会话模拟（10 万会话，人群结构为大众 c0 占 46%、低注 c1 占 37%、高额 c2 占 17%）显示，95Kai 的下注总额和旋转次数与原始表基本持平，97BG_adj 的下注总额有小幅提升、旋转次数略降；跨会话生命周期口径下，两张表相对 zero 的终身下注提升都很小（95Kai +0.7%、97BG_adj +4.6%），判定为与基线基本持平。

真实 A/B 的结果和模拟预读出现了方向性差异：

- **95Kai vs zero**：全面小幅提升——下注、留存都略好，且 RTP 低了约 2 个百分点但 profit 反而更高。模拟当时判定为基本持平，说明模拟器**低估了** FGadj（尾部收窄）这个方向对留存的正面贡献。
- **97BG_adj vs zero**：下注额上升，但 1 日、3 日留存和 number_bets 都下降，大部分玩家表现不佳。模拟当时同样判定为小幅正向、基本持平，说明模拟器**低估了**提高 BG 中奖率这个杠杆对留存的负面代价。

这两条方向相反的偏差，是后续模拟器矫正的直接动因。

## 五、模拟器矫正与 41 表相关性分析

2026 年 7 月 7 日，模拟器上线了两处矫正：

- **`--hit-floor`**：在 Esscher 投影里新增 P(0) 的上限约束，与已有的 `--hit-cap`（P(0) 下限）对称。
- **`--return-rtp-correction`**：修正回访字典里"破产后回访率虚高"的选择偏差——用 within-user 固定效应检验发现，破产本身对是否回访几乎没有因果作用，老口径把这层相关性错当成了因果。

在此基础上，对 zero-kernel sweep 里全部 41 张表做了一轮相关性分析：

- **整体驱动因素**：分配给 BG 的 RTP 占比（bg_share）和 BG mean 与 bet_med 的相关系数都在 0.82 左右（Spearman rho 0.80-0.85）；trigger_pct 与 bet_med 的相关系数是 −0.72（rho −0.82）；BG variance 本身与 bet_med 几乎无关（r=0.12）。也就是说，真正决定业务表现的是 RTP 分配在哪个环节，而不是赔付方差本身。
- **赔付区间**：0–0.5x 这个"垃圾赔付"区间和下注量、留存都是负相关，是与 one_and_done 相关性最强的单项（r=+0.64）——占比越高，玩家越容易玩一把就走。5–10x 是唯一专门跟留存挂钩的区间，占比越高 sess_mean 越高、one_and_done 越低，和下注量本身的关联不明显。

用 zero、shi、deploy（`zero_lt95tr_e15_BGadj`）、bg97 四张表交叉验证，这套相关性结构能正确排出两端：deploy 在所有驱动因素上都占优（bg_share 最高、trigger 最低），实际表现也最好；shi 在两个最强的区间信号上都垫底（5–10x 占比塌到 2.0%，20–50x 却冲到 58.1%），实际表现也最差。

需要说明：这是相关关系而非因果关系，41 张表的样本量不算大，且每张表各区间占比加起来是 100%、彼此并不独立，这套结论更适合做方向性参考，不是精确的归因依据。

另外两条经验规律也在这个阶段被确认：

- 玩家下注金额本身方差极大，且不容易被数学表左右，所以用下注数量而不是下注金额做主要参考指标更稳。
- 模拟器目前还不能很好地预测留存。

**设计初衷 → 真实作用**

- **97bgtr+BGadj（在 95bgtr 上把 RTP 提到 97，多余份额全部走 BG 赔付区间重分配、trigger 保持 0.30% 不变）**：初衷是验证"用 BG 重分配来花掉多余 RTP"这条路（对照另一条尚未上线、靠提 trigger 花 RTP 的 TriggerAdj）。真实 num_bet +25%、留存 D1 +1.8pp，且增益随资历放大（old 段 +35.7%、beginner 段投注 +88%），但 GGR 转负（−6.5 万，RTP 101.1，均刨暗保底后）。**作用 = 确认"BG 重分配"是可行的花 RTP 方式**（与 97BG 那种"提中奖率"截然不同、效果相反），代价是 RTP 提到 97 会让平台阶段性让利；与 95bgtr（RTP 95.9、GGR 仍正）并列，给出了"要不要为多约 1pp 的活跃/留存去付出转负 GGR"的清晰决策点。

**综合：数学表设计杠杆 × 真实效果总览**

把四期六张表按"改了什么设计杠杆"归类，真实 A/B 结果给出每个杠杆的方向性结论：

| 设计杠杆 | 代表表 | 设计初衷 | 真实效果（同期） | 结论 |
|---|---|---|---|---|
| Esscher 平移 RTP（不改分布形状） | 95Kai / 93Kai | 只调 RTP 高低，作中性锚点 / 探压缩边界 | 95Kai ≈ zero（中性）；93Kai 再深即伤留存（资深段更甚） | **中性杠杆**，甜点约在 RTP 95，过深转负 |
| 提 BG 中奖率（压空转 70%→35%） | 97BG_adj | 用高频小奖改善体验 | 全面变差、越资深越差（num_bet −27%、D1 −4.2pp） | ✗ **证伪**：高频小奖稀释体验、伤留存 |
| CBO 训练重塑 BG 赔付节奏 | 95bgtr | 让算法自由演化学赔付节奏 | 首次全面跑赢 95Kai，GGR 仍为正 | ✓ **有效**，项目正向拐点 |
| BG 重分配花掉多余 RTP（提到 97） | 97bgtr+BGadj | trigger 不变，多余 RTP 走 BG 区间 | 增益随资历放大、留存升，但 GGR 转负 | ✓ **可行**，代价 = 平台让利 |
| 低强度换黏性（校准用表） | normal_shi | 拿模拟↔线上背离的表校准 | 下注量垫底但留存不塌、beginner 反超 | 揭示**下注量 ↔ 留存背离** |

一句话贯穿：**决定数学表业务价值的，不是 RTP 的高低本身，而是"多出/少掉的 RTP 花在哪个赔付环节"**——把 RTP 交给 CBO 去重塑 BG 节奏（95bgtr/97bgtr）能同时拉动下注与留存；单纯平移 RTP（95Kai/93Kai）是中性；粗暴提 BG 中奖率（97BG）则适得其反。这与第五节 41 表相关性分析（bg_share 与 bet_med 正相关 0.82、5–10x 区间专门挂留存）在方向上完全一致——真实 A/B 从业务侧印证了模拟侧的归因。

**关于投注力度（单发金额）**：各表**中位单发**都很接近（多在 1.0–2.5），说明**典型玩家的单笔押注不太被数学表左右**；差异几乎全在**均值单发**——好表（95bgtr、97bgtr 这类高 RTP 的 CBO 表）把头部大户的单笔强度顶上去（三期 97bgtr 均值单发 5.2 vs Default 3.5），而 97BG 那种伤体验的表则相反。即数学表主要通过"让愿意加注的头部玩家加得更狠"来放大投注力度，而非改变大众的下注习惯——这也解释了为什么总下注额（含鲸鱼）比 num_bet 更敏感、更该用中位/缩尾来读。

**关于大/中/小投注额玩家**：把每期再按玩家期内总投注额切三档后，数学表的作用落点非常清楚——

- **小投注额玩家（<200 元，约 63% 人数、仅约 14% 投注额）**：D1 留存只有约 5%，以"来一次就走"为主；各表之间几乎无差异（他们还没体验到表的区别就流失了）。**数学表对这群人基本无影响。**
- **中投注额玩家（200–2000 元，约 29%）**：D1 约 20%，表差异开始显现——三期 CBO 表已拉开（97bgtr 中玩家 num_bet 259、净亏 −56 vs 95Kai 230/−88）。
- **大投注额玩家（≥2000 元，约 8% 人数却占约 86% 投注额，D1 约 55–60%）**：**业务价值集中地，数学表效应最大、也最关键**。三期 97bgtr 对大玩家 RTP 102.6、**GGR −13.6 万（平台向大鲸让利）**、玩家净亏中位从 −385 收窄到 −190（缩尾均值甚至转正 +248，大玩家整体反赢）、留存 56.8——明确是"用大玩家让利换其活跃/留存"；95bgtr 对大玩家 GGR 仍 +6.4 万、留存 56.4，更平衡。反例：97BG 一期大玩家 num_bet −16%、留存持平（大玩家也不买账"提中奖率"），shi 二期大玩家留存 58.7≈95Kai（黏性不掉）。

**贯穿结论**：数学表的业务影响**几乎完全由中/大额玩家驱动**——占人数六成的小额玩家对表不敏感、来去一次性；占投注额 86% 的大额玩家才是决定 GGR 与留存的关键，而 CBO 好表（BGTR 系）的作用机制正是**对大额玩家适度让利（RTP↑、GGR↓）以换取其更高的活跃与留存**。这与前面"越资深越买账""增益集中在头部"的分层结论完全一致，共同指向数学表真正的作用对象：**留得住、下得起注的中大额玩家**。

## 八、高价值玩家专属表与 reward shaping 方向

从已有数据看，高价值玩家会大幅影响整体业务指标——一期评估里 c2 高额高频客群仅占 17% 的用户，却贡献了绝大部分下注总额的方差。基于这个发现，目前已经在探索给高价值玩家分配专属数学表，已经完成的工作有两条线：

- **HMM day-state 定义**：以 12 小时 session 间隔划定"高价值日"，用 handle、session-length、pure-return 三种 reward 训练并对比过（2026 年 8 月 11 日完成），尚未上线或正式上报。
- **静态定义**：按"终身下注前 10%"划定高价值玩家，已有 4 个训练完成但未上报的 checkpoint（2026 年 7 月 23 日至 8 月 4 日之间）。

这两套定义相关但不是同一批人——个体层面只有 42.7% 的静态高价值玩家曾被 HMM 定义标记过高价值日；另，HMM 定义是按天切换的状态，需要工程侧支持按天把用户路由到对应的表，这是架构层面的改动，不是简单加一个 cluster 就能完成的。

reward shaping 方向上，针对高价值玩家专属表，计划改用百分位类指标，而不是终身汇总数（即现有 canonical reward 那种对全量玩家做加总或取均值的口径，比如 lifetime_value、lifetime_total_bet、engagement_depth）：

- p90 下注总额（p90 total bet）
- p90 下注量（p90 spin/bet count）
- 
用这套 reward 已训练出相应数学表 highvalue 表。预计未来也会上真实 A/B 测试，上线后重点关注的验收标准就是这几个百分位指标本身是否达到预期，而不是看整体均值或中位数。

## 九、下一步计划

三大主线（与本报告结论直接衔接），外加若干支撑项。

### 9.1 数学表特性整理 × 玩家适配

把"哪张表"和"哪类人"系统地对上——本报告已证明不同分层（HMM 状态、日龄、投注额）对同一张表的响应差异很大，需要把这层规律沉淀成可复用的适配规则。

- **建表特性库**：给每张表登记结构画像——`bg_share`（BG 占 RTP 比）、`trigger_pct`、各赔付区间占比（0–0.5x「垃圾赔付」/1–5x/5–10x/20–50x…）、BG mean/variance、理论 RTP、FG 占比。即第五节相关性分析里的那些驱动因子，标准化成可检索的"表画像"。
- **建"表 × 玩家分层"适配矩阵**：把表画像与本报告三个分层维度（HMM 生命周期、日龄、投注额）交叉，登记每张表对哪类人最优。已知规律：CBO 表（BGTR 系）对**中/大额、资深玩家**增益最大；97BG 式"提中奖率"对各段都差；shi"低量却黏人"另有其位。
- **产出**：一张"表特性 × 玩家分层 → 推荐度"矩阵，作为选表层（MAB）的先验与冷启动依据。

### 9.2 实际 RTP 与理论 RTP 偏差的归因与修正

各表**实测 RTP（含 FG、已刨 kakutei）与设计理论 RTP 有系统性偏差**（如 95Kai 理论 95%/实测 ~92%、97bgtr 理论 97%/实测 ~101%）。RTP 是营收护栏，偏差不解决就无法用理论值做营收预测与合规。

- **分解来源**：(a) **FG 实现率**——理论 RTP 假设 FG 按期望触发/赔付，实际触发频率 + 玩家买 FG 行为使 FG 贡献偏离；(b) **玩家行为选择**——下注档位、停手时机、连亏后行为让实现分布偏离理论；(c) **样本/窗口**——短窗 + 鲸鱼尾部使实测 RTP 方差大；(d) 缩尾/口径差异。
- **做法**：逐表把 `实测RTP = BG实测 + FG实测` 拆开各自对理论，定位偏差主因，反馈给 **Esscher 投影层**（RTP 收敛约束）与**模拟器校准**（第五节 `--hit-floor`/`--return-rtp-correction` 矫正的延续），让"理论 RTP"更贴近上线实测。
- **验收**：偏差收敛到可接受带内（例如 ±1pp），且能按表/按人群预测。

### 9.3 HMM × Fancy Stuff 结合：一类玩家一张最优表 + 阶段性线上更新

**目标**：用 HMM 把玩家分类（生命周期 T1/S1/S2/S3，或高价值 day-state），**每一类用 CBO 训练/选出一张最优表**（per-cluster table），而非全体一张——本报告已证明分层响应差异真实存在，一类一表有明确收益空间。

- **已有基础**：第八节的 HMM day-state 专属表 + 静态高价值表 checkpoint；`train_online.py` 的在线训练能力。
- **落地链路**：CBO（为每类生成最优表）→ HMM（按天给玩家打状态标签）→ MAB/路由层（把对的表分给对的人）→ 同期 A/B 验收（百分位口径）。
- **阶段性线上更新**：把第一节的"上线 → 收数 → 用真实结果校准模拟器 → 重训下一版表 → 再上线"闭环**常态化为在线滚动更新**，每类表按阶段迭代；与 SS07 的 AI/MAB 调控层（含 Micro-MAB 因果实验、在线训练）联动上线。
- **工程前置**：HMM 按天状态需要工程侧支持**按天把玩家路由到对应表**（架构改动），是本主线的关键前置。

### 9.4 支撑项

- **验收口径先定好**：专属表上真实 A/B 时，主指标改用**百分位**（p90 num_bet、p90 total_bet）+ 分层 D1/D3/D7 留存，全部走**同期组间**对比（沿用本文口径），避免整体均值/中位掩盖头部效应。
- **BG 重分配 vs 提 trigger**：把 97bgtr 的 BGadj 与尚未上线的 TriggerAdj 做同期 A/B，直接比两种"花掉多余 RTP"的方式。
- **更多学习维度**：把 near-miss 等盘面信息加入模拟（需开发侧支持）。
- **待补历史缺口**：一期/二期的绝对 GGR 与鲸鱼（大额客群）贡献占比，可在同期窗口补一版，用于校准模拟器对高价值人群的偏差。

## 十、high_player_test_v1：高价值玩家专属表首个真实 A/B

第八节提出的「高价值玩家专属表」正式推上真实同期 A/B（独立方案详见 `SS03_high_player_test_v1.md` / 对应 Confluence 页）。首次把两张面向高价值玩家的 CBO 表与现行 default 同期对照，验证「高 RTP」与「低波动·高价值训练」两条路线。

**方案**：`MOD(user_id, 100)` 尾号后两位分流，为期 **21 天**。

| 组 | 数学表 | 占比 | 尾号 | RTP | 设计取向 |
|---|---|---:|---|---:|---|
| A | BGTR97_Saitekika_v3 | 30% | 00–29 | 96.9% | 高 RTP（+2pp 走 BG）、BG 命中↑、FG 依赖↓ |
| B | BGTR95_HMM_Highvalue_v1 | 30% | 30–59 | 95.2% | 同 RTP、HMM 高价值训练、**波动最低(SD 93 vs 127)** |
| default | 95Kai | 40% | 60–99 | 94.9% | 现行对照 |

![high_player_test_v1 AB 实验分组图](data/output/ab_testing/high_player_test_grouping.png)

**对照逻辑**：A vs default = 加 RTP + 改 BG 结构；B vs default = 同 RTP 换低波动形态（干净形态对照）；A vs B = 高 RTP vs 低波动·高价值训练。

**主指标**（高价值 = 终身前 10%，同期组间，中/均/均99，刨 kakutei）：p90 total_bet / p90 num_bet、D1/D3/D7；护栏 = 各组实测 RTP 贴近设计、全体留存不滑。**编码** `high_player_test`：default=0 / A=1 / B=2。
