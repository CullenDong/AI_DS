## 1. 假设（Hypothesis）

> **给处于不同生命周期状态（HMM: T1 / S1-low / S2-engaged / S3-escaped）的玩家开启个性化挽留策略（ON），相较不开启（OFF/holdout），能显著提升其 D7 留存与转化，且不恶化净收入、付费与风控护栏。**

派生子假设（每 HMM 状态独立检验）：
- H-S3（escaped/流失）：挽留对高流失风险人群提升最大（重点验证）。
- H-S1（low）：挽留能把低活跃拉回活跃。
- H-S2（engaged）：挽留对已活跃人群边际提升有限（可能无效，验证是否浪费成本）。
- H-T1（初始）：挽留对新客/首触的早期留存影响（含义待确认）。

启动后**冻结**，改变假设 → 新建实验。

---

## 2. 背景与目标

个性化挽留系统已上线并按生命周期给玩家打 `CR_FISHING_V1:Tk` 标签、施加加成。但**当前没有干净的对照**来量化"挽留到底带来多少增量、对哪类人有效"。本实验建立**挽留 ON vs OFF 的随机对照**，并用**处理无关的 HMM 状态**分层，回答：挽留的因果增量、以及对哪种生命周期状态最该投入。

---

## 3. 分析人群与分组

- **subject_type**：FM01 玩家账号（当前用户 ID 体系，对齐 PRD §9.3，不依赖 OneID）。
- **eligibility（筛选逻辑，语义口径）**：
  1. 排除 **风控**（sticky，套利农场已含在内）。
  2. 排除 **dynamic_rtp 臂**（吃 RTP，混淆挽留主效应）。
  3. 剩余 = 挽留 AB 人群 = **挽留臂(ON)** + **holdout(OFF)**，两臂均 RTP-off。
- **分层维度（HMM 产出，处理无关，分组时冻结）**：`T1 / S1 low / S2 engaged / S3 escaped`。
  - 从行为序列算出，与是否被挽留无关 → 两臂都能算 → 无 post-treatment 偏差。
- **处理臂**：Control = 挽留 OFF（holdout）；Variant = 挽留策略 ON。
- **终端格**：4 状态 × 2 臂 = **8 格**（详见 `AB分组方案设计_v0.1.md` §2.4）。

> 完整分割图与终端组清单见分组方案文档 §2.2–§2.4。

## 4. 变量（Control / Variant）

| | 内容 | 约束 |
|---|---|---|
| **Control** | 不施加个性化挽留（holdout，保持基准体验） | 可追溯的基准配置版本 |
| **Variant** | 开启现行个性化挽留策略 `CR_FISHING_V1`（含加成/触达） | Phase 1 仅一个 Variant；策略实质变化则结束本实验重开 |

> 若后续要比"挽留策略 A vs B"，属另一实验（两臂皆 ON，在挽留臂内再切），本实验不含。

## 5. 指标

### 5.1 主指标（primary_metric，启动前冻结）
- **D7 留存率**：cohort 玩家在入组日 +7 自然日仍有任意 FM01 有效投注的比例。
- 统计主体 = 玩家；分析人群 = ITT（合格且已分组主体）；窗口 = D7；时区 = 北京（UTC+8）。

### 5.2 次要指标（观察，不用于胜负判定）
- D1、D3 留存；状态跃迁率（S3→S2/S1 回流、S1→S2 提升）；人均投注次数/额。

### 5.3 护栏指标（guardrail，每项设停止阈值）
| 护栏 | 口径 | 停止阈值（示例，待批准） |
|---|---|---|
| 人均净收入 / ARPU | (投注−派彩)/人 | Variant 相对 Control 下降 > 5% |
| 付费率 | 付费用户占比 | 下降 > 3pp |
| 整层 RTP | 派彩/投注 | Variant RTP 越界（如 >100%，防挽留放水被套利） |
| 客诉 / 投诉率 | 投诉工单/人 | 显著上升 |
| 曝光完整性 | exposure/assignment | < 阈值触发数据质量 invalid |

## 6. 统计设计

- **analysis_population**：ITT（默认）。未曝光的 assignment 仍进主分析，曝光完整性作诊断。
- **固定周期**：预设 minimum_duration 与目标样本，到达前不因普通显著性提前停（PRD §5.7）。
- **alpha = 0.05（双侧）**，**power = 0.8**（具体值由数据负责人批准）。
- **分层分析**：每个 HMM 状态内做两比例检验（ON vs OFF）；多状态用预注册的多重比较校正（如 Holm）。

### 6.1 每臂样本量需求（主指标 D7 留存）

`n/arm = (z_a/2 + z_b)^2 · [p1(1-p1)+p2(1-p2)] / (p1-p2)^2`

| HMM 状态 | 基线 D7（待标定） | MDE +3pp | MDE +5pp | MDE +8pp |
|---|---|---|---|---|
| T1 初始 | 15% | 2,399 | 903 | 374 |
| S1 low | 10% | 1,771 | 683 | 291 |
| S2 engaged | 30% | 3,760 | 1,374 | 546 |
| S3 escaped | 5% | 1,056 | 432 | 197 |

> **关键约束**：需求为**每臂每状态**。Control 来自 holdout（人群较小），是样本瓶颈——
> 若单波不够，**跨波累计**到目标样本再读数（固定周期 + 目标样本双条件）。
> 最终数字需待 **HMM 各状态实际人数分布** + **真实基线 D7** 标定后锁定。
> 计算脚本：`jobs/ab_testing/ab_sample_size.py`。

## 7. 数据质量与 SRM

- **双层 SRM**：assignment 层 + exposure 层分别比对实际 vs 预设比例（PRD §5.6）。
- **分状态 SRM**：8 个终端格的实际比例与预期比对，任一 P0 失败 → 结论锁定。
- **曝光口径**：ON/OFF 两臂**同一曝光触发口径**（如"进入游戏大厅/收到挽留触点位"），去重。
- **右截断**：末尾入组 cohort 的 D7 未成熟时不计入主分析（见 §9 时间线）。
- 详见 PRD 数据质量清单。

---

## 8. 灰度扩量与紧急停止

- **ramp_plan**：小流量起步 → 每阶段检查（SRM / 护栏 / RTP / QA / 上阶段最短观察）→ 逐步扩量。
  扩量**不改变已分组用户组别**。
- **emergency_stop_rule**：触发条件 = 护栏越界 / 严重 SRM / RTP 异常放水 / 客诉激增。
  停止后新增决策回到基准（挽留 OFF）；已产生加成/订单不回滚；恢复需新批准。

## 9. 时间线与验证窗口（示例，日期以排期为准）

| 阶段 | 日期（示例） | 内容 / 验证 |
|---|---|---|
| G0 设计冻结 | 2026-08-20 | 假设/指标/HMM 口径/护栏阈值/样本量全部关闭 to_be_confirmed |
| QA + 数据链路就绪 | 08-20 ~ 08-27 | 测试身份验证分组；assignment/exposure 双事件打通 |
| 灰度 ramp 起步 | 2026-08-28 | 小流量；查 SRM/护栏/RTP，健康后扩量 |
| 全量运行 | 2026-09-04 | 达比例上限；进入正式 cohort 累计 |
| 最短运行 minimum_duration | 14 天（覆盖 2 个完整周周期） | 09-04 ~ 09-18 为主 cohort 入组窗口 |
| **D7 验证窗口成熟** | 2026-09-25 | 最后入组 cohort（09-18）+7 天 → 主指标可读 |
| 结论评审 readout | 2026-09-26 | 主指标/护栏/SRM/区间/样本成熟度出报告 |
| 决策 & rollout | 2026-09-28+ | ship→灰度全量 / extend / stop / investigate |

**验证时间（观测窗口）口径：**
- 每个 cohort 的 D1/D3/D7 分别在其**入组日 +1/+3/+7** 成熟。
- **主指标 D7** 需等实验窗口内**最后一个 cohort** 也满 7 天才完整（示例中 09-25）。
- 实验末尾 7 天入组的 cohort，其 D7 未成熟 → **右截断**，不进主分析或触发 extend。
- minimum_duration 取 14 天以**覆盖完整周内节律**（工作日/周末差异），避免周期偏差。

## 10. 决策框架（ship / extend / stop / investigate）

按 PRD §10.2，逐 HMM 状态判定，再汇总：

| 主指标(D7) | 护栏 | 数据质量 | 结论 |
|---|---|---|---|
| 达统计+业务门槛 | 可接受 | 正常 | **ship**（该状态开挽留） |
| 方向对但样本/窗口不足 | — | 正常 | **extend** |
| 效果≈0 或负向 | — | 正常 | **stop**（该状态不投挽留，省成本） |
| 正向 | 护栏越界 | — | **investigate**（权衡） |
| — | — | 无效/联合SRM | **investigate**（锁定结论排查） |

> 允许**分状态差异化结论**：如 S3/S1 ship、S2 stop（对已活跃人群挽留无增量则不投）。
